# SOXL B전략 시그널 봇

`SOXL B전략.txt` 의 규칙을 감시해서 **매수·매도 신호가 나면 텔레그램으로 알린다.**
주문은 내지 않는다. 증권사 계좌와 연결되지 않는다.

```
진입   RSI(12) ≤ 25            (1시간봉 종가)
발동   평가수익 +10% 도달 → 트레일링 켜짐
청산   발동 후 고점 대비 -3%
손절   진입가 -30%             ← 이 전략의 본체
```

## 구조

```
GitHub Actions (15분마다)          Cloudflare Worker "soxl-bot"
  bot.py                             ├ POST /tg       텔레그램 명령 (즉시)
   ├ Yahoo 5분봉 60일 (시간외 포함)   ├ GET  /d/{경로}  대시보드
   ├ 정규장 → 1시간봉 (7봉/일)   ───► ├ GET/POST /sync  KV 읽기·쓰기
   ├ RSI(12) Wilder                  ├ POST /notify    텔레그램 발송 대행
   ├ 상태머신    ← 정규장 봉만        └ cron           15분 디스패치 · 감시견
   ├ 시간외 예고 ← 알림 전용                  │
   ├ 급등락 ±5%  ← 알림 전용                  │
   └ /sync·/notify 호출                       │
                                       KV "STATE"  ← 상태 단일 원본

GitHub 에는 텔레그램 토큰도 Cloudflare API 토큰도 두지 않는다.
BOT_SYNC_SECRET 하나로 Worker 통로만 열어준다.
```

ET 04:00(프리장) ~ 20:00(애프터장) 내내 돈다. 정규장이 아니어도 알림은 나간다.

## 15분 트리거는 Cloudflare 가 잡는다

GitHub 의 `schedule` 은 못 믿는다. 실측이다.

```
2026-08-26 ~ 08-28   기대 실행 ~140회 / 실제 schedule 트리거 1회
```

그 사이 KV 가 08-27 14:00 UTC 봉에 22시간 얼어 있었고, 진입후 고점이
$121.35 로 멈춰 트레일링 스탑이 $117.71 (정상값 $119.47) 로 어긋나 있었다.
그래서 15분 트리거는 Cloudflare cron 이 잡고, Worker 가 `workflow_dispatch`
로 Actions 를 깨운다. `check.yml` 의 `schedule` 은 예비로 남겨둔다.

`bot.py` 는 **멱등**하다. "지금 몇 시냐"가 아니라 "KV 의 `last_bar` 이후
확정된 봉이 있냐"로 판단하므로, cron 이 늦거나 건너뛰어도 다음 실행이
밀린 봉을 전부 처리한다.

## 봉 구조 — 절대 건드리지 말 것

ET 09:30~**15:59** 를 UTC 정각으로 resample → **하루 7봉**.

ET 16:00 의 1분짜리 봉을 포함하면(8봉/일) 5년 누적이
**+2,600% → +518%**, MDD 가 **-66% → -76%** 로 무너진다.
`strategy.py` 의 `RTH_CLOSE` 를 고치면 다른 전략이 된다.

## 시간외 — 알림은 즉시, 판정은 정규장 종가

시간외 봉은 **매매 판정에 절대 넣지 않는다.** 넣으면 5년 실측이 이렇게 무너진다.

```
정규장만 (현행)    CAGR 100.6% / MDD -40.8% / 하드스탑  2
시간외 포함        CAGR  34.1% / MDD -81.5% / 하드스탑 12
```

그래서 시간외에는 "예고"만 보낸다. 문구에 **※ 아직 확정 아닙니다** 가 박혀 있다.
상태(`status`/`entry`/`peak`)는 정규장 1시간봉 종가로만 바뀐다.

| 예고 | 조건 |
|---|---|
| 🔵 매수 조건 충족 | FLAT + 예상 RSI(12) ≤ 25 |
| 🟢 발동선 도달 | HOLD + 현재가 ≥ 진입가 +10% |
| 🔴 트레일링 스탑 이탈 | ARMED + 현재가 ≤ 고점 -3% |
| ⚫ 하드스탑 이탈 | 현재가 ≤ 진입가 -30% |

조건이 붙어 있는 동안은 한 번만 보낸다. 풀렸다가 다시 성립하면 또 보낸다.

시세는 **ET 04:00~19:59** 만 받아진다. 그 바깥(야간·국내 주간거래)에는 마지막 봉이
몇 시간씩 그대로 남는다. 그걸 현재가로 쓰면 예고·급등락이 묵은 가격으로 나가므로,
**틱이 20분 이상 묵으면 예고·급등락을 통째로 건너뛴다** (`TICK_STALE_SEC`).
`/status` 에는 `장 종료 · … (N시간 전)` 으로 표시된다.

## 급등락 알림

**직전 정규장 종가** 대비 현재가가 ±5% 를 넘으면 알린다. 프리장·애프터장 포함이다.
10%, 15% 로 더 벌어지면 그 단계마다 다시 알린다. 같은 날 같은 방향에서 같은 단계는
한 번뿐이다. 매매 신호가 아니라 시세 알림이므로 상태를 바꾸지 않는다.

## 검증

```bash
python verify_backtest.py     # Polygon 원본 CSV 필요 (로컬 전용)
```

문서의 **+2,600% / MDD -66.3% / 58거래 / 승률 87.9%** 를 재현하면 PASS.
`strategy.py` 를 수정했으면 반드시 다시 돌린다.

## 텔레그램 명령

| 명령 | 동작 |
|---|---|
| `/status` | 현재 상태와 트리거까지 거리 |
| `/entry 123.45` | 진입가를 실제 체결가로 정정 |
| `/skip` | 신호 났지만 안 삼 → 미보유로 되돌림 |
| `/sold` | 매도 완료 → 미보유 |
| `/hold 123.45` | 수동으로 보유 등록 |
| `/peak 130.00` | 진입후 고점 수동 보정 (액면분할 등) |
| `/id` | 이 대화의 chat_id 확인 |

`/skip` 은 "이번 봉만 무시"가 아니라 **미보유로 되돌리는** 명령이다.
RSI 가 계속 25 이하면 다음 봉에 또 신호가 온다.

## 알아둘 것

- **액면분할** 시 KV 의 `entry`·`peak` 가 조정되지 않아 하드스탑이 오발동한다.
  분할이 있으면 `/entry`·`/peak` 로 직접 보정할 것.
- **첫 실행(콜드스타트)** 은 받아온 봉을 통째로 재생해 현재 포지션을 복원하고
  요약 하나만 보낸다. 과거 신호를 쏟아내지 않는다. KV 를 비우면 다시 그렇게 된다.
- **알림을 놓칠 수 있다.** 미국장은 한국 새벽이다. 하드스탑 알림은
  15분 간격으로 3회 발송되지만, 그래도 못 보면 다음 날 아침에 실행하게 된다.
- **yfinance 는 비공식 스크래퍼다.** 깨지면 `TWELVEDATA_API_KEY` 를
  Secrets 에 넣어두면 자동으로 예비 소스로 넘어간다.
- **하루 한 번은 반드시 연락이 온다.** 거래일에는 장 마감 후 일일 요약,
  미국 휴장일에는 감시견이 휴장 안내를 보낸다. **평일에 아무 연락도 없으면
  고장이다.** (주말은 조용한 게 정상)
- **GitHub 60일 규칙** — 저장소에 활동이 없으면 스케줄 워크플로가 자동
  비활성화된다. 하루 1회 `signals.log` 커밋으로 활동을 유지하고,
  그래도 멈추면 Cloudflare 감시견이 텔레그램으로 알린다.
